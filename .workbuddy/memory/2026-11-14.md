## 主页横向滑动「拖后强制弹回」修复（已实跑验证）

### 根因（关键）
`ui::Widget::onEnter → updateSizeAndPosition` 在前端页面**每次进场景**时用节点自身尺寸重放 `setContentSize(580,128)`（== 当前 3.x 节点尺寸=视口尺寸）。兼容层 `CCScrollViewCompat::setContentSize` 按 2.x 语义重写，把该 3.x 语义调用误当"设置容器内容尺寸"，导致：
- `container->setContentSize(视口尺寸)` + `setInnerContainerSize(视口尺寸)` → **inner 容器尺寸被砸回视口尺寸**，滚动余量=0；
- 拖动变成纯"橡皮筋"超滚，松手（bounce 开启时）必然弹回原点。
- 影响：主页头像行、底部导航，以及所有滚动视图内按钮的命中。

### 修复（client/compat/CCScrollViewCompat.cpp/.h）
1. `setContentSize` 增加「节点尺寸重放」守卫：传入 size == 当前 3.x 节点尺寸（用 `cocos2d::Node::getContentSize()` 取非虚基类值）→ 直接 return；`_compatContainer==NULL` 也按 2.x 完全空操作。
2. `setBounceable(b)` 恢复 `_compatBounceable=b` + `setBounceEnabled(b)`（inner 尺寸修好后关闭 bounce 不再破坏滚动，拖到边界硬停）；惯性保留（2.x 松手有 deaccel）。
3. `init()` 默认 `setBounceEnabled(false)`、`_compatBounceable` 默认 false（对齐 2.x `m_bBounceable=false`），ccbi `bounces=true` 由 `CCScrollViewLoader` 显式打开。
4. `onTouchEnded` 恢复纯转发（去掉临时的 clamp-freeze hack）。

### 验证（tools/ab_verify_bounce2.ps1，真·点住→拖动→松手前截图→松手后截图）
- 头像行：`BEFORE=408996 / MID=401992 / MIDHOLD=402275 / AFTER=397496` → 拖动真实滚动，松手停留（AFTER≠BEFORE），截图确认整行左移后停住。
- 底部导航：拖动硬停（MID==MIDHOLD），松手按 2.x delegate 吸附到 `minContainerOffset` 并切换左箭头，最右露出「联盟」。
- 日志确认 `setContentSize size=(540,100) ... replay=1`（重放被跳过）、`nodeContent` 保持内容尺寸、`applyOffset`/冻结数值正确。

## 滚动视图内按钮点击无响应修复（头像1/空位加号，已实跑验证）

### 根因（引擎层，两类叠加）
1. **命中坐标**（此前会话已修）：`Menu::getItemForTouch` 用 `isScreenPointInRect` + `getWorldToNodeTransform`，链路含 CHAIN[6] 的 0.5 页面缩放，实测命中数学正确（hit=1）。之前"2× 错位"结论是误读 parent-space 的 boundingBox 为世界坐标。
2. **真正的根因：回调从未被设置**。3.x 上游 `cocosbuilder::NodeLoader::parsePropTypeBlock` 有 `if(!isJSControlled())` 守卫；老工程私改版（老 `extensions/CCBReader/CCNodeLoader.cpp:760`）**注释掉了该判断**，无论 jsControlled 都解析 C++ selector。framedButton.ccbi、TeamPage 等 ccbi 头部 jsControlled=1 → 3.x 端静默 return nullptr → `MenuItemLoader::onHandlePropTypeBlock` 收到 blockData=NULL → `MenuItem::_callback` 为 NULL → `activate()` 空转，无任何日志。全量 274 个 BLOCK 属性中 59 个中招（onFrameButton×17、onFrame1-6、onShowDetail1-4、onJoinBattle、onShowRank、onSkillCenter、getRewardBtn、onPieceBook）。

### 修复
- `engine/.../cocosbuilder/CCNodeLoader.cpp::parsePropTypeBlock`：对齐老版，去掉 jsControlled 分支（始终走 C++ selector 解析，解析失败才落回回调数组兜底）。`parsePropTypeBlockCCControl` 老版保留了守卫 → 不动。

### 诊断手段（保留，env 门控）
- `HAIZEI_MENU_DIAG=1`：`[MenuDiag] begin/TEST/CHAIN/onTouchEnded/onTouchCancelled`（CCMenu.cpp）+ `[CCBDiag] prop/BLOCK apply/parsePropTypeBlock/setCallback`（CCNodeLoader/CCMenuItemLoader）+ `[MenuDiag] activate`（CCMenuItem.cpp）。
- 排查链：activate callback=NULL → load 期 setCallback 未调用 → BLOCK apply blockData=00000000 → parsePropTypeBlock js=1 走了 JS 兜底 → 对照老版源码定位。

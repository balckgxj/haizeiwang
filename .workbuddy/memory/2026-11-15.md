路线（用户确认）：无 Mac、只有普通 Apple ID → **GitHub Actions 云端 macOS 构建 + Windows Sideloadly 签名**（7 天重签）。

工程现状盘点：
- 引擎 cocos2d-x 3.17.2 的 CMake **原生支持 iOS**（`cocos/platform/CMakeLists.txt` 有 APPLE/IOS 分支、CCEAGLView 等齐全；`CocosConfigDefine.cmake` 靠 `CMAKE_SYSTEM_NAME=iOS`+`IOS` 变量；curl/freetype/jpeg/png/tiff/websockets/openssl 都有 `prebuilt/ios`）。
- `platform_bridge/libOS/iOS/` 有老手游原生 .mm 实现；`client/Platform/GamePlatform.mm` 存在。
- `third_party`（protobuf2.5/jsoncpp/tinyxml）纯源码编译，无平台问题。
- 之前只有 Windows：`client/CMakeLists.txt` 硬编码 win32 桥接、`/FI` 强制包含、`/WHOLEARCHIVE`。

本次改动：
1. **根 CMakeLists.txt**：新增 IOS 分支 → MACOSX_BUNDLE app（proj.ios/main.m+AppController.mm+RootViewController.mm）、资源用 `cocos_mark_multi_resources` 打进 .app、`-Wl,-force_load` 替代 /WHOLEARCHIVE（静态初始化器注册问题同样存在于 ld）、`cocos_pak_xcode` 用 proj.ios/Info.plist（横屏）、部署目标 12.0、CODE_SIGNING_ALLOWED=NO。
2. **client/CMakeLists.txt**：IOS 时桥接源换 libOS/iOS glob（.mm/.m）+ libPlatform.cpp；GamePlatform/*.mm 并入；`/FI` → `-include`（Clang 连写）；链 Foundation/UIKit/Security/SystemConfiguration/CFNetwork。
3. **proj.ios/**：从引擎 tests/cpp-empty-test 拷贝模板；AppController.mm 的 AppDelegate import 改为同 include 路径。
4. **haizei_compat.h**：CCMessageBox 非 Windows 落 printf；新增非 MSVC CRT 映射（_stricmp→strcasecmp、_snprintf→snprintf 等）。
5. **.github/workflows/ios-build.yml**：macos-14，`cmake -G Xcode -DCMAKE_SYSTEM_NAME=iOS ...` → xcodebuild 未签名 → Payload 打 ipa → artifact；失败传日志。
6. **.gitignore**：排除 build/(8.4G)、_tools/、reference/、*.dmp 等；可推送体积约 650MB，无 >80MB 单文件。
7. **docs/IOS_PACKAGING.md**：全流程文档（推送→云构建→Sideloadly→连本机服：netConfig.cfg 改局域网 IP+防火墙放行 9999/8080）。
